# Review round 2 — adversarial, UX, accessibility (2026-10-06)

Five static reviews of the `feat/calltime-prototype` branch, each against `docs/SPEC.md`,
`docs/DESIGN.md` and `docs/ux/GUIDELINES.md`: security (every action, route and public surface),
family-facing UX, creative-team UX, shared primitives/shell accessibility (with computed WCAG
contrast for every token pair), and domain logic (call engine, change tracking, iCalendar, import,
MCP). Everything marked **fixed** landed in the five commits after `3de3942`; the rest is listed so
nothing is lost.

## Security

| Sev | Finding | Status |
|---|---|---|
| Medium | Public audition signup had no rate limit: one script could take every slot and spam PII into the staff list. | **fixed** — per-device and per-family limits (DB-backed, like login) |
| Medium | An editor could change a cast member's email, invite "them", accept as themselves and inherit read access to every other production the person or their wards are in. | **fixed** — editors can add a missing email but not replace one; claiming a person record needs edit rights on *every* production they're in; staff/person invites are bound to the invited email |
| Low | Dead invite links stayed usable as a password oracle. | **fixed** — validity checked before the password |
| Low | Login timing revealed whether an email had an account. | **fixed** — bcrypt always runs |
| Low | Signing in left the previous device session alive for 60 days. | **fixed** — `createSession` revokes the cookie's old session |
| Low | Last-admin guard was a check-then-act race. | **fixed** — counted under a row lock |
| Low | CR injection in the audition `.ics`; tab/CR formula prefixes in the CSV export. | **fixed** |
| Low | Person-target block calls survived un-casting / deleting a person. | **fixed** — dropped in the same transaction; engine only resolves people still in the cast |
| Low | MCP string inputs unbounded; loose UUID regex. | **fixed** — 4000-char caps; strict UUID |
| Low | No security headers. | **fixed** — no-referrer, nosniff, frame deny, permissions policy |
| Low | MCP endpoint has no rate limiting (keys are 192-bit, so brute force is impractical). | open |
| Info | Demo mode makes the world an org admin: it can mint API keys and send invites to real emails. | **fixed** — demo accounts can't create or use API keys, send invites or reset links, replace emails, or change the demo password |
| Info | Invite, manage and calendar tokens are stored in plaintext because the UI re-displays the URLs. | accepted |
| Info | Sibling "add another" passes the manage token in a query string (`?from=`). | open — move to a short-lived cookie |

Verified fine: every action/page scopes foreign ids to the authorized production/org; drafts never
reach families (pages, feed, digest, push); MCP keys cannot exceed their creator's rights and die on
demotion; `safeNextPath`; raw SQL fragments are parameterized; push endpoints are allowlisted.
